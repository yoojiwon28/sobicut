# PWA 전환 & 웹푸시 알림 설계

작성일: 2026-07-27
대상: 프론트엔드, 백엔드 공통 참고 문서

## 배경

기존 React Native(Expo) 앱을 웹앱으로 전환하기로 결정. 스택은 **Vite + React + vite-plugin-pwa**.
원래 기획의 "소비 잦은 시간대 진입 시 푸시 알림"(예: 월요병 텅장 컷, 불금 입구 컷) 기능은 네이티브 푸시 대신 **웹푸시(Web Push API)**로 대체한다.

## PWA란

일반 웹사이트에 아래 두 가지를 추가해서 네이티브 앱처럼 동작하게 만든 것.

- **매니페스트 파일**: 앱 이름, 아이콘, 실행 시 브라우저 주소창 없이 풀스크린으로 띄우는 설정 등을 담은 JSON. 이게 있어야 브라우저가 "홈 화면에 추가" 기능을 제공함.
- **서비스워커**: 브라우저 백그라운드에서 동작하는 스크립트. 파일 캐싱(오프라인 지원)과 푸시 수신을 담당.

앱스토어 배포 없이 브라우저에서 바로 설치되고, 홈 화면 아이콘 실행 + 백그라운드 알림 수신이 가능해짐.

## 웹푸시 동작 흐름

1. 사용자가 앱 접속 → 브라우저가 알림 권한 요청 (`Notification.requestPermission()`)
2. 권한 허용 시 브라우저가 `PushSubscription` 생성 (사용자·기기별 고유 구독 정보, endpoint + key 포함)
3. 프론트가 이 구독 정보를 백엔드로 전송, 유저 계정과 매핑해서 DB 저장
4. 백엔드가 알림 조건 충족 판단 (예: 금요일 밤 진입) → 저장된 구독 정보로 암호화된 푸시 메시지 발송
5. 메시지는 브라우저 벤더의 푸시 중계 서버(Chrome=FCM, Safari/Firefox는 각자 서버)를 거쳐 사용자 기기 도달
6. 기기에서 서비스워커가 백그라운드에서 깨어나 `push` 이벤트 수신 → `showNotification()`으로 OS 알림 표시
7. 사용자가 알림 탭 → `notificationclick` 이벤트에서 앱으로 포커스 이동

## VAPID 키

웹푸시 발신자를 증명하는 공개키/개인키 쌍. 이게 없으면 아무나 구독 주소를 알아내 스팸을 보낼 수 있음.

- **생성**: 백엔드에서 1회 생성 (Node면 `web-push` 라이브러리에 생성 커맨드 내장)
- **공개키**: 프론트 코드에 포함, 구독 시 브라우저에 전달
- **개인키**: 백엔드에만 보관, 실제 발송 시 서명에 사용. 절대 프론트/레포에 노출 금지

## 오프라인 캐싱 범위

전부 캐싱하지 않고 데이터 성격에 따라 구분:

- **캐싱**: 앱 껍데기(로고, 레이아웃, JS/CSS 번들), 로그인 화면 등 정적 UI → 오프라인에서도 흰 화면 방지
- **캐싱 안 함**: 가계부 내역, 지갑 온도계, 리포트 그래프 등 실시간성 데이터 → 오프라인 시 "인터넷 연결 후 새로고침" 안내로 처리 (과하게 캐싱하면 옛날 데이터가 최신처럼 보여서 오히려 혼란)

## 설치 유도 UX

브라우저 기본 설치 아이콘은 존재감이 약해서 앱에서 직접 유도 UI 필요.

- **Android/데스크톱 크롬**: `beforeinstallprompt` 이벤트를 잡아 커스텀 버튼으로 설치 유도 가능
- **iOS Safari**: 이 이벤트 자체가 없음. "공유 버튼 → 홈 화면에 추가"를 텍스트/이미지로 직접 안내해야 함
- **중요 제약**: iOS는 홈 화면에 설치된 PWA에서만 웹푸시가 동작함. 사파리 탭 상태로는 알림이 아예 안 옴 → 알림이 핵심 기능이므로 설치 유도 타이밍이 중요 (예: 회원가입 직후, 첫 가계부 기록 직후 등 관심도가 높을 때)

## FE / BE 역할 분담

| 항목 | 담당 | 내용 |
| --- | --- | --- |
| VAPID 키 생성 | 백엔드 | 1회 생성, 개인키 서버 보관, 공개키 프론트 공유 |
| 서비스워커 / 매니페스트 설정 | 프론트 | vite-plugin-pwa로 구성 |
| 알림 권한 요청 + 구독 생성 UI | 프론트 | 권한 요청, 구독 정보 백엔드 전송 |
| 구독 정보 저장 | 백엔드 | 유저-구독 매핑 DB 테이블 |
| 알림 발송 로직 | 백엔드 | 소비 패턴 조건 판단 + `web-push` 등으로 발송 |
| 설치 유도 UI | 프론트 | 플랫폼별(안드로이드/iOS) 분기 처리 |
| 오프라인 캐싱 전략 | 프론트 | 정적 리소스만 캐싱, 데이터는 실시간 유지 |

## 참고 제약사항

- iOS Safari 웹푸시는 16.4+ 버전부터 지원, 반드시 홈 화면 설치 필요
- 서비스워커는 HTTPS(또는 localhost)에서만 동작
